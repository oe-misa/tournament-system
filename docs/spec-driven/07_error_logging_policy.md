# 07 Error Logging Policy

## 基本方針

- ユーザー操作で起こり得る業務エラーは例外メッセージを画面または API に返す。
- 想定外のシステムエラーは Laravel 標準の例外処理に委ねる。
- 業務エラーとシステムエラーを区別する。
- パスワード、API token、セッション、個人情報の過剰なログ出力は禁止する。

## エラー分類

### 業務エラー

ユーザーの状態や入力により正常に拒否するエラー。

例:

- 年間登録が期限切れで大会エントリーできない。
- 段位が不足して大会エントリーできない。
- エントリー締切を過ぎている。
- 定員に達している。
- 会員キャンセルの期限を過ぎている。
- 管理者キャンセルの対象ではない。
- 現在段位より下へ段位申請しようとした。
- 未処理段位申請が既にある。
- 年間登録の翌年度申請開始日前に更新しようとした。
- 翌年度年間登録が既に完了している。
- 年間登録申請が承認前である。

扱い:

- Service では `Symfony\Component\HttpKernel\Exception\HttpException` を投げる。
- Web Controller は catch して session `error` または validation errors として返す。
- API Controller は catch して JSON `message` と HTTP status を返す。
- 原則として error log には出さない。

### 認可エラー

権限不足による拒否。

例:

- 非管理者が管理画面へアクセスする。
- 非管理者が段位申請を承認・却下しようとする。
- 非管理者が年間登録申請を承認・却下しようとする。

扱い:

- middleware または Service で 403 とする。
- 監査ログが必要になった場合は別途方針を追加する。

### バリデーションエラー

入力形式不正。

例:

- 必須項目未入力。
- 文字数超過。
- 存在しない rank id。
- 順位やスコアの範囲外。

扱い:

- Laravel validation で処理する。
- Web はフォームへ戻す。
- API は Laravel 標準の 422 JSON とする。

### 競合エラー

同時操作や状態変化によるエラー。

例:

- おみくじを同日に同時実行した。
- 段位申請が既に処理済み。
- 年間登録申請が既に処理済み。
- エントリー定員が直前で満員になった。
- 状態遷移済みの大会を更新しようとした。

扱い:

- 必要に応じて DB transaction と lock を使う。
- ユーザーには再実行可能なメッセージを返す。
- 想定内の競合は error log に出さない。

### システムエラー

想定外の例外。

例:

- DB 接続失敗。
- migration 不整合。
- 未定義プロパティや null 参照。

扱い:

- Laravel 標準ログに記録する。
- ユーザーには汎用エラーを返す。
- 再現手順、URL、ユーザーID、request id の記録を検討する。

## HTTP status 基準

| Status | 用途 |
| --- | --- |
| 200 | 表示・取得成功 |
| 201 | API 作成成功 |
| 302 | Web フォーム成功/失敗後のリダイレクト |
| 403 | 権限不足、業務上の実行不可 |
| 409 | 状態競合、重複 pending、処理済み再処理 |
| 422 | 入力値不正 |
| 500 | 想定外のシステムエラー |

## 現在の実装方針

### EntryService

- 年間登録期限切れ、段位不足、締切後、定員到達は `HttpException(403)`。
- 重複エントリーは既存データを返し、エラーにしない。
- 会員キャンセルの締切超過は 403。
- 管理者キャンセルが許可されない場合は 403。

### MembershipService

- 翌年度更新開始日前は `HttpException(403)`。
- 翌年度登録済みは `HttpException(403)`。
- 年数入力は廃止したため、年数不正エラーは発生しない。
- 承認前の年間登録申請は pending として扱う。

### RankRequestService

- 現在段位より下の申請は `HttpException(422)`。
- pending 重複は `HttpException(409)`。
- 非管理者操作は `HttpException(403)`。
- 処理済み申請の再処理は `HttpException(409)`。

### OmikujiController

- 既に引いている場合は status メッセージで返す。
- DB 制約競合も既に引いている扱いで返す。

## ログ出力基準

現時点では明示的な業務ログは実装しない。
次の要件が出た時点で監査ログ設計を追加する。

- 管理者操作履歴。
- 年間登録の支払い・承認履歴。
- 段位変更履歴の監査。
- 大会エントリーのキャンセル履歴。

## 禁止事項

- パスワードをログに出さない。
- remember token、session id、API token をログに出さない。
- メールアドレス以外の個人情報を不用意にログに出さない。
- 画面に stack trace を表示しない。
