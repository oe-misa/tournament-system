## 目的

大会情報の公開、会員のログイン、大会エントリー、成績閲覧、プロフィール管理、年間登録更新、段位申請、日次おみくじを一元化する。
管理者は大会管理、成績入力、段位申請の承認/却下を行う。

## ユーザー種別

### 公開ユーザー

- 公開トップを閲覧できる。
- 会員入口からログインまたは新規登録へ進める。

### 会員

- ログイン後に会員ダッシュボードを利用できる。
- プロフィールを確認・更新できる。
- 年間登録を更新できる。
- 大会一覧・大会詳細を閲覧できる。
- 条件を満たす大会へエントリーできる。
- 自分の成績一覧を閲覧できる。
- 自分の段位以上へ段位申請できる。
- 段位申請履歴、ステータス、担当者、管理者コメントを閲覧できる。
- 1 日 1 回だけおみくじを引ける。

### 管理者

- 会員機能を利用できる。
- 管理ダッシュボードを利用できる。
- 大会を作成・編集・削除できる。
- 会員一覧を閲覧し、会員情報を編集できる。
- 大会ごとの成績を入力・更新できる。
- 段位申請を一覧し、未処理申請を承認または却下できる。
- 段位申請の処理時に管理者コメントを残せる。
- 段位申請を承認した場合、対象ユーザーの段位を更新する。

## 機能仕様

### 認証

- Laravel Breeze の Web 認証を使用する。
- 未ログインで会員・管理者画面にアクセスした場合、ログイン画面へリダイレクトする。
- 管理者画面は `is_admin = true` のユーザーのみ利用できる。

### ダッシュボード

- 会員名、現在段位、年間登録期限を表示する。
- 年間登録が未登録または期限切れの場合、現在状態の確認を促す。
- 本日のおみくじ結果、またはおみくじを引くボタンを表示する。
- 会員情報、大会登録、大会結果、年間登録、段位申請、段位申請履歴への導線を表示する。
- 管理者の場合、管理メニューと未処理件数を表示する。

### プロフィール

- 氏名、メールアドレスを更新できる。
- 任意でパスワードを更新できる。
- 現在段位と年間登録期限を表示する。
- 段位変更はプロフィールでは行わず、段位申請から行う。
- アカウント削除時は現在パスワードを要求する。

### 年間登録

- 年間登録の年度期間は 4 月 1 日から翌 3 月 31 日までとする。
- 年間登録は 1 年度単位のみとし、複数年更新や任意期間更新はできない。
- 年間登録は会員が更新画面から実施する。
- 申請前に更新対象年度と更新可否をプレビューする。
- 登録履歴は `memberships` に保存する。
- 現在有効な期限は `users.membership_expires_at` に保存する。
- 現在有効な会員は、3 月 10 日以降に翌年度分へ更新できる。
- 現在有効な会員は、3 月 9 日以前に翌年度分へ更新できない。
- 期限切れ会員および未登録会員は、現在年度分として更新する。
- 期限切れ会員および未登録会員は、更新前に現在状態の確認を促す。
- 同じ年度の更新が既に存在する場合、重複更新はできない。
- 画面表示では `MembershipService::preview()` の結果を使って更新可否と対象期間を判断する。
- 更新実行では `MembershipService::renew()` を使い、`memberships` の履歴作成と `users.membership_expires_at` の更新を同一トランザクションで行う。

### 大会

- 会員は大会一覧を開催日順に閲覧できる。
- 会員は大会詳細を閲覧できる。
- 大会にはタイトル、説明、公開状態、開催日、エントリー締切、定員、最低段位レベルを設定できる。
- 最低段位レベルは表示時に級/段ラベルへ変換する。
- 公開状態は `draft / recruiting / closed / finished` を持つ。
- `draft` は会員一覧に表示しない。
- `recruiting` はエントリー受付中とする。
- `closed` と `finished` は会員一覧に表示するが、エントリーは不可とする。

### 大会エントリー

- 会員は大会詳細からエントリーできる。
- 年間登録が未登録または期限切れの場合、エントリーできない。
- ユーザー段位レベルが大会の最低段位レベル未満の場合、エントリーできない。
- エントリー締切を過ぎている場合、エントリーできない。
- 定員が設定されていて満員の場合、エントリーできない。
- 同一ユーザー・同一大会の重複エントリーは作成しない。
- 既存エントリーがある場合は成功扱いで既存データを返す。
- エントリー可否判定は `EntryService` に集約する。
- 定員判定はトランザクション内で行い、同時エントリー時の取りこぼしを防ぐ。
- エントリー登録は `entries` に `entry` 状態で保存する。
- 既存エントリーがある場合は新規作成せず、そのまま返す。

### 成績

- 会員は自分の成績のみ閲覧できる。
- 成績には大会、開催日、順位、スコアを表示する。
- 管理者は大会ごとにエントリー済み参加者の成績を入力・更新できる。

### 段位

- 段位は `ranks.level` の数値で管理する。
- 表示ラベルは `RankLabel` で変換する。
- 基本対応は以下とする。
  - 0: 無段（F〜E級）
  - 1: 初段（D級）
  - 2: 弐段（C級）
  - 3: 参段（B級）
  - 4〜10: A級（四段〜十段）

### 段位申請

- 会員は現在段位以上の段位へ申請できる。
- 現在段位より下の段位へは申請できない。
- 未処理の申請が既にある場合、新規申請できない。
- 申請時に備考を登録できる。
- 申請は `pending` として保存する。
- 会員は自分の申請履歴を確認できる。

### 段位申請管理

- 管理者は全申請を一覧できる。
- 未処理申請のみ承認・却下できる。
- 承認時は申請ステータスを `approved` にし、対象ユーザーの `rank_id` を更新する。
- 却下時は申請ステータスを `rejected` にする。
- 承認・却下時は担当管理者、処理日時、管理者コメントを保存する。

### おみくじ

- 会員は 1 日 1 回おみくじを引ける。
- 結果は `大吉/吉/中吉/小吉/凶` のいずれかとする。
- 同日に既に引いている場合、新しい結果は作成しない。
- 結果はダッシュボードに表示する。
- 結果のみ保存する。
- 同日重複防止は `omikuji_draws.user_id + drawn_on` の一意制約を前提にする。
- 既に引いている場合は、画面上は「本日は引きました」と扱う。

### API

- Sanctum 認証済みユーザー向け API を提供する。
- API は Web の一部主要操作を扱う。
- API 対象:
  - 自分自身の取得
  - 大会一覧・詳細
  - 大会エントリー
  - 自分の成績一覧
  - 段位申請作成

## 実装前提

### Dashboard

- 管理者の未処理件数は段位申請の `pending` 件数と、エントリー済みだが成績未入力の件数で構成する。

### 大会エントリー

- `EntryService::entry()` は年間登録、段位、締切、定員、重複を確認する。
- 同一会員・同一大会の重複は、既存データを返すことで冪等に扱う。
- 定員チェックは transaction と lock を併用する。

### 大会エントリーキャンセル

- 会員は自分のエントリーをキャンセルできる。
- 会員キャンセルはエントリー締切の 10 日前まで可能とする。
- 締切 10 日前を過ぎてから締切までは管理者のみキャンセルできる。
- 管理者は大会編集画面から参加者ごとのキャンセルを行える。
- キャンセル時は `entries.status` を `cancelled` に更新する。
- キャンセル済みのエントリーは再エントリーで `entry` に戻せる。

### 会員管理

- 管理者は会員一覧を閲覧できる。
- 管理者は会員詳細を閲覧できる。
- 管理者は会員編集画面で氏名、メールアドレス、段位、年間登録期限、管理者権限を更新できる。
- 会員一覧では段位、年間登録期限、管理者権限、関連件数を表示する。

### 段位申請

- 申請時に `requested_rank_id`、`requested_level`、`note` を保存する。
- `pending / approved / rejected` の3状態で管理する。
- 承認時は `users.rank_id` を更新する。
- 承認・却下時は `approved_by` / `rejected_by`、`approved_at` / `rejected_at`、`admin_comment` を保存する。

### 年間登録

- `users.membership_expires_at` が現在有効期限の真実となる。
- `memberships` は更新履歴として残す。
- 更新可能かどうかは 3/10 を境に判定する。

### おみくじ

- `omikuji_draws` は同一ユーザー・同一日で一意にする。
- 同日重複は新規作成せず、既に引いた扱いで返す。

### API

- API は `auth:sanctum` 前提で利用する。
- レスポンスは JSON とする。
- 現行公開範囲は会員情報、大会一覧・詳細、大会エントリー、自分の成績一覧、段位申請作成までとする。

## 主要データ

- `users`
  - `name`, `email`, `password`, `rank_id`, `membership_expires_at`, `is_admin`
- `ranks`
  - `kyu`, `dan`, `level`
- `tournaments`
  - `title`, `description`, `status`, `event_date`, `entry_deadline`, `capacity`, `min_rank_level`
- `entries`
  - `user_id`, `tournament_id`, `status`
- `results`
  - `user_id`, `tournament_id`, `placing`, `score`, `note`
- `memberships`
  - `user_id`, `start_date`, `end_date`, `note`
- `rank_requests`
  - `user_id`, `rank_id`, `requested_rank_id`, `requested_level`, `status`, `note`, `approved_by`, `approved_at`, `rejected_by`, `rejected_at`, `admin_comment`
- `omikuji_draws`
  - `user_id`, `result`, `drawn_on`
