# Requirements

## 目的

本プロジェクトは、福岡かるた会向けの会員管理・大会運営システムである。
会員はログインして大会確認、エントリー、成績確認、段位申請、年間登録更新、おみくじを利用する。
管理者は大会管理、段位申請の承認・却下、成績入力を行う。
API は会員向けの主要操作を外部から扱えるようにする。

## 背景

- 会員が大会情報や自身の状態をオンラインで確認・操作できるようにする。
- 管理者の事務処理を Web 上に集約する。
- 段位、年間登録、大会エントリー、成績を一元管理する。
- 既存の Laravel アプリを基盤に、会員向けと管理者向けの業務を整理している。

## 対象ユーザー

- ゲスト
  - ランディングページ、会員案内を閲覧する。
- 会員
  - ログインして各機能を利用する。
- 管理者
  - 会員機能に加え、管理画面の業務を行う。
- API 利用者
  - `auth:sanctum` 前提で会員向け API を利用する。

## 機能一覧

### 1. 認証・共通

- ログイン
- 新規登録
- ログアウト
- パスワード再設定
- メール認証関連画面
- プロフィール編集
- プロフィール削除

### 2. 公開ページ

- ランディングページ表示
- 会員向け案内ページ表示
- マイページの公開リンク表示

### 3. 会員ダッシュボード

- ログイン後の要約表示
- 会員の段位表示
- 管理者の場合の未処理件数表示
- 本日のおみくじ結果表示

### 4. 大会

- 大会一覧表示
- 大会詳細表示
- 大会の開催日、締切、定員、最低段位条件の表示

### 5. 大会エントリー

- 会員による大会エントリー
- 年間登録期限チェック
- 段位条件チェック
- エントリー締切チェック
- 定員チェック
- 重複エントリー防止

### 6. 成績

- 会員向け成績一覧表示
- 管理者による大会ごとの成績入力
- 成績の登録・更新

### 7. 段位申請

- 会員による段位申請
- 申請時の段位一覧参照
- 申請履歴表示
- 管理者による承認
- 管理者による却下

### 8. 年間登録

- 会員による年間登録更新
- 更新可能期間のプレビュー表示
- 期限や更新可否の案内表示
- 更新履歴保存

### 9. おみくじ

- 会員による1日1回のおみくじ
- 重複実行の防止
- 結果履歴保存

### 10. 管理画面

- 管理ダッシュボード
- 大会 CRUD
- 段位申請一覧
- 段位申請の承認・却下
- 大会ごとの成績入力

### 11. API

- 自分の会員情報取得
- 大会一覧取得
- 大会詳細取得
- 大会エントリー
- 成績一覧取得
- 段位申請作成

## データ一覧

- `users`
  - 名前、メール、パスワード、段位、年間登録期限、管理者フラグ
- `ranks`
  - 段位、級/段、レベル
- `tournaments`
  - 大会名、説明、開催日、締切、定員、最低段位条件
- `entries`
  - ユーザーと大会のエントリー
- `results`
  - 大会成績、順位、スコア、備考
- `memberships`
  - 年間登録の履歴
- `rank_requests`
  - 段位申請、状態、申請理由、承認・却下情報
- `omikuji_draws`
  - おみくじ結果と実施日

## 権限一覧

- ゲスト
  - 公開ページと認証画面の利用
- 会員
  - 大会閲覧、エントリー、成績閲覧、段位申請、年間登録更新、おみくじ
- 管理者
  - 会員機能に加え、大会管理、段位申請管理、成績入力
- API 利用者
  - `auth:sanctum` で認証した会員

## 外部連携

- 現状は外部決済連携なし
- 現状は外部通知連携なし
- API は Sanctum 認証を使用

## 非機能要件

- Laravel による Web / API 実装
- 認証は Breeze ベース
- API は Sanctum ベース
- 日本語 UI / 日本語メッセージ
- 主要一覧はページネーションを使用
- 競合が起こり得る処理ではトランザクションやロックを利用する
- エラーは共通方針に従って 403 / 409 / 422 / 500 を使い分ける
- ログ出力は個人情報を出しすぎない

## 制約事項

- 年間登録は現行実装では申請後に即時更新する
- 年間登録の承認フローと決済フローは現行実装では未導入
- 大会エントリーは会員の年間登録と段位条件に依存する
- 大会定員と締切によってエントリー可否が変わる
- 段位申請は現在段位より下を申請できない
- 同日のおみくじは重複実行できない
- 管理者機能は `auth + admin` middleware で保護する

## 完成条件

- 会員がログインして主要機能を利用できる
- 管理者が大会管理、段位申請管理、成績入力を行える
- API で会員情報、大会、成績、段位申請が扱える
- 各業務処理でエラー条件が適切に制御される
- 現行画面と API が routes 上で到達可能である

## 確定事項

- 会員機能は Web と API で提供する
- 管理機能は Web で提供する
- 大会一覧と詳細は会員が閲覧できる
- 会員は大会エントリーできる
- 会員は成績一覧を閲覧できる
- 会員は段位申請を作成し、履歴を確認できる
- 会員は年間登録更新ができる
- 会員はおみくじを1日1回引ける
- 管理者は大会 CRUD を行える
- 管理者は段位申請を承認・却下できる
- 管理者は大会成績を入力できる
- API は `me`、`tournaments`、`entries`、`results`、`rank-requests` を提供する

## 仮説事項

- ランディングページと会員向け案内ページは、今後も導線ページとして残す
- 年間登録の承認・支払いフローは別フェーズで追加する可能性がある
- 管理者向け会員管理は別フェーズで追加する可能性がある
- 大会の公開状態管理は必要に応じて追加する可能性がある
