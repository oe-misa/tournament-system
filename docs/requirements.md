# Requirements

## 目的

本プロジェクトは、福岡かるた会向けの会員管理・大会運営システムである。
会員はログインして大会閲覧、エントリー、成績閲覧、段位申請、年間登録更新、おみくじを利用できる。
管理者は大会管理、段位申請の承認・却下、成績入力を行える。
API は会員向けの一部主要操作を提供する。

## 背景

- 会員が大会情報や自身の状態をオンラインで確認・操作できるようにする。
- 管理者の大会運営、段位申請対応、成績入力を Web 上で行えるようにする。
- 段位、年間登録、大会エントリー、成績、おみくじを一元管理する。

## 対象ユーザー

- ゲスト
  - ランディングページや会員入口を閲覧する。
- 会員
  - ログインして会員機能を利用する。
- 管理者
  - 会員機能に加え、管理画面で運用を行う。
- API 利用者
  - `auth:sanctum` 前提で API を利用する会員。

## 機能一覧

### 1. 認証・共通

- ログイン
- 新規登録
- ログアウト
- パスワード再設定
- メール認証関連画面
- プロフィール編集
- アカウント削除

### 2. 公開ページ

- ランディングページ表示
- 会員向け案内ページ表示
- 会員入口表示

### 3. 会員ダッシュボード

- ログイン後の要約表示
- 会員の段位表示
- 年間登録期限の表示
- 本日のおみくじ結果表示
- 会員メニュー導線表示
- 管理者の場合の未処理件数表示

### 4. プロフィール

- 氏名、メールアドレスの更新
- 任意のパスワード更新
- 現在段位の確認
- 現在の年間登録期限の確認
- パスワード確認によるアカウント削除
- プロフィール画面では段位更新はしない

### 4.1 プロフィール表示項目

- 氏名
- メールアドレス
- 現在段位
- 年間登録期限
- 段位申請への導線

### 5. 大会

- 大会一覧表示
- 大会詳細表示
- 大会タイトル、説明、開催日、締切、定員、最低段位条件の表示
- 大会一覧は開催日順に並べる
- 大会詳細は大会内容と参加条件を表示する
- エントリー可能かどうかは詳細画面で判断する

### 5.1 大会データ項目

- タイトル
- 説明
- 開催日
- エントリー締切
- 定員
- 最低段位レベル

### 6. 大会エントリー

- 会員による大会エントリー
- 会員による大会エントリーキャンセル
- 年間登録期限チェック
- 段位条件チェック
- エントリー締切チェック
- 定員チェック
- 重複エントリー防止
- 既存エントリーがある場合は重複エラーではなく成功扱い
- エントリー状態は `entry`
- キャンセル状態は `cancelled`

### 6.1 エントリー制約

- 年間登録が未登録または期限切れなら不可
- ユーザー段位レベルが大会最低段位レベル未満なら不可
- 締切日時を過ぎたら不可
- 定員に達していれば不可
- 同一会員・同一大会は 1 件のみ
- 会員キャンセルは締切 10 日前まで
- 締切 10 日前を過ぎてから締切までは管理者のみキャンセル可
- キャンセル済みデータは再エントリーで復帰可能

### 6.2 エントリーキャンセル

- 会員は自分のエントリーをキャンセルできる
- 管理者は大会編集画面から各エントリーをキャンセルできる
- キャンセル可否は `EntryService` が判定する
- キャンセル処理は `entries.status` を `cancelled` に更新する
- キャンセル済みのエントリーは再エントリーで `entry` に戻せる

### 7. 成績

- 会員向け成績一覧表示
- 管理者による大会ごとの成績入力
- 成績の登録・更新
- 会員側は自分の成績のみ閲覧する
- 管理者側は大会ごとに参加者単位で入力する

### 7.1 成績データ項目

- 大会名
- 開催日
- 順位
- スコア
- 備考

### 8. 段位申請

- 会員による段位申請
- 申請時の段位一覧参照
- 申請履歴表示
- 管理者による承認
- 管理者による却下
- 管理者コメントの保存
- 申請対象は現在段位以上の段位
- 現在段位より下には申請できない
- 未処理申請がある場合は新規申請できない

### 8.1 段位データ項目

- 段位レベル
- 級/段表示
- 申請備考
- 申請状態
- 管理者コメント
- 承認者/却下者
- 承認/却下日時

### 9. 年間登録

- 会員による年間登録更新
- 更新可能期間のプレビュー表示
- 期限や更新可否の案内表示
- 更新履歴保存
- 年度単位で管理する
- 4/1 から翌 3/31 を 1 年度とする
- 現在有効な会員は 3/10 以降に翌年度分へ更新できる
- 期限切れまたは未登録会員は現在年度分を更新する
- 更新結果は `users.membership_expires_at` に反映する

### 9.1 年間登録表示項目

- 現在の期限
- 今回の登録期間
- 更新可否メッセージ
- 更新ボタン

### 10. おみくじ

- 会員による 1 日 1 回のおみくじ
- 重複実行の防止
- 結果履歴保存
- 結果は `大吉 / 吉 / 中吉 / 小吉 / 凶`
- ダッシュボードから直接実行する

### 11. 管理画面

- 管理ダッシュボード
- 大会 CRUD
- 段位申請一覧
- 段位申請の承認・却下
- 大会ごとの成績入力
- 管理ダッシュボードでは未処理段位申請件数と成績未入力件数を表示する
- 大会一覧から作成、編集、削除、成績入力へ遷移する

### 11.1 管理者画面の対象データ

- 大会一覧
- 未処理段位申請一覧
- 成績未入力件数

### 12. API

- 自分の会員情報取得
- 大会一覧取得
- 大会詳細取得
- 大会エントリー
- 自分の成績一覧取得
- 段位申請作成
- API は現行では会員向けの一部だけを公開する
- API 返却は JSON を前提とする

### 12.1 API 返り値の考え方

- `me` は会員自身の基本情報と段位を返す
- `tournaments` は一覧と詳細を返す
- `entries` はエントリー成功/失敗を返す
- `results` は成績一覧を返す
- `rank-requests` は申請作成結果を返す

## データ一覧

- `users`
  - 名前、メール、パスワード、段位、年間登録期限、管理者フラグ
- `ranks`
  - 段位マスタ
  - `kyu`, `dan`, `level` を持つ
  - `level` は 0 〜 10 の比較値として使う
- `tournaments`
  - 大会タイトル、説明、開催日、締切、定員、最低段位レベル
- `entries`
  - ユーザーと大会のエントリー
- `results`
  - 大会成績、順位、スコア、メモ
- `memberships`
  - 年間登録履歴
- `rank_requests`
  - 段位申請、状態、備考、承認・却下情報
  - `pending / approved / rejected`
- `omikuji_draws`
  - おみくじ結果と実施日
- `personal_access_tokens`
  - Sanctum API token

### 主要データの補足

- `users.rank_id` は現在段位を示す
- `users.membership_expires_at` は現在の年間登録期限を示す
- `entries.status` は現行運用では `entry` が中心
- `results` は同一大会・同一ユーザーで 1 件
- `omikuji_draws` は同一ユーザー・同一日で 1 件

## 権限一覧

- ゲスト
  - 公開ページと認証画面の利用
- 会員
  - 大会閲覧、エントリー、成績閲覧、段位申請、年間登録更新、おみくじ
- 管理者
  - 会員機能に加え、大会管理、段位申請管理、成績入力
- API 利用者
  - `auth:sanctum` で認証した会員

## 外部連携

- 外部決済連携は未実装
- 外部通知連携は未実装
- API 認証は Sanctum を使用する

## 非機能要件

- Laravel による Web / API 実装
- 認証は Breeze ベース
- API は Sanctum ベース
- 日本語 UI / 日本語メッセージ
- 一覧系はページネーションを使用する
- 競合が起こり得る処理ではトランザクションやロックを利用する
- エラーは共通方針に従って 403 / 409 / 422 / 500 を使い分ける
- ログ出力は個人情報を出しすぎない

## 制約事項

- 年間登録は 4/1 から翌 3/31 までの年度単位で扱う
- 年間登録は会員による更新画面から実施する
- 現在有効な会員は 3/10 以降に翌年度分へ更新できる
- 期限切れ会員と新規会員は現在年度分として更新する
- 大会エントリーは年間登録期限と段位条件に依存する
- 大会定員と締切によってエントリー可否が変わる
- 段位申請は現在段位より下を申請できない
- 同日のおみくじは重複実行できない
- 管理者機能は `auth + admin` middleware で保護する
- 段位ラベルは `RankLabel` に従って表示する
- API は Sanctum 認証済みユーザーに限定する

### 段位表示ルール

- `0`: 無段（F〜E級）
- `1`: 初段（D級）
- `2`: 弐段（C級）
- `3`: 参段（B級）
- `4`: 四段（A級）
- `5`: 五段（A級）
- `6`: 六段（A級）
- `7`: 七段（A級）
- `8`: 八段（A級）
- `9`: 九段（A級）
- `10`: 十段（A級）

### 大会参加条件表示

- `min_rank_level = 0`: A,B,C,D,F〜E級
- `min_rank_level = 1`: A,B,C,D級
- `min_rank_level = 2`: A,B,C級
- `min_rank_level = 3`: A,B級
- `min_rank_level >= 4`: A級

## 完成条件

- 会員がログインして主要機能を利用できる
- 管理者が大会管理、段位申請管理、成績入力を行える
- API で会員情報、大会、成績、段位申請作成が扱える
- 各業務処理でエラー条件が適切に制御される
- 現行画面と API が routes 上で到達可能である

## 確定事項

- 会員機能は Web で提供する
- 管理機能は Web で提供する
- API は会員向けの一部機能を提供する
- 大会一覧と詳細は会員が閲覧できる
- 会員は大会エントリーできる
- 会員は成績一覧を閲覧できる
- 会員は段位申請を作成し、履歴を確認できる
- 会員は年間登録更新ができる
- 会員はおみくじを 1 日 1 回引ける
- 管理者は大会 CRUD を行える
- 管理者は段位申請を承認・却下できる
- 管理者は大会成績を入力できる
- ダッシュボードは会員向け導線と管理者向け件数表示を持つ
- API は `me`、`tournaments`、`entries`、`results`、`rank-requests` を提供する
