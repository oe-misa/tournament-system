# Requirements Question Map

## 目的

Requirements GPT がどの種類の質問を出すかを、再利用しやすい形でまとめる。

## 質問形式

- 各質問は `Q-XXX` で識別する。
- 状態は `未確定 / 仮説 / 確定` のいずれかを付与する。
- ひとつの質問に対して、必要なら補足質問をぶら下げる。
- 回答後に疑問が残るときは、派生質問として新しい `Q-XXX` を追加する。

### 記載例

- `Q-001 [未確定] この機能は Batch ですか API ですか Front ですか`
- `Q-002 [仮説] 画面は一覧 + 詳細 + 編集の3画面構成を想定していますが問題ないですか`
- `Q-003 [確定] 認証は既存ログインを利用する前提で進めます`

## 共通の質問セット

- Q-001 [未確定] 何を作るか。
- Q-002 [未確定] 誰が使うか。
- Q-003 [未確定] 何ができれば完成か。
- Q-004 [未確定] 主要機能は何か。
- Q-005 [未確定] どのデータを扱うか。
- Q-006 [未確定] どの権限を分けるか。
- Q-007 [未確定] 外部連携はあるか。
- Q-008 [未確定] 今回やらないことは何か。
- Q-009 [未確定] 非機能要件はあるか。
- Q-010 [未確定] 既存システムや制約はあるか。

## 使い分け

- 共通質問で土台を作る。
- 該当しない種類は聞かない。
- 画面系は `Front` と `FrontEnd` を混同しない。
- バッチ処理は UI 質問を含めない。
- API は画面仕様ではなく契約仕様に寄せる。
- 質問一覧は Requirements.md の `質問一覧` に転記する。
- 質問が確定したら状態を `確定` に更新する。
- 仮説で進める項目は、仮説の前提を1行で書く。
