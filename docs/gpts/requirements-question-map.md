# Requirements Question Map

## 目的

Requirements GPT がどの種類の質問を出すかを、再利用しやすい形でまとめる。

## 共通の質問セット

- 何を作るか。
- 誰が使うか。
- 何ができれば完成か。
- 主要機能は何か。
- どのデータを扱うか。
- どの権限を分けるか。
- 外部連携はあるか。
- 今回やらないことは何か。
- 非機能要件はあるか。
- 既存システムや制約はあるか。

## Batch の質問セット

- 実行契機は何か。
- 定期実行か手動実行か。
- 実行頻度はどれくらいか。
- 入力元と出力先は何か。
- 冪等性は必要か。
- 失敗時は自動再試行するか。
- 再実行は誰がどう行うか。
- 実行時間に制約はあるか。
- 処理件数の規模はどれくらいか。

## API の質問セット

- 認証方式は何か。
- 利用者は誰か。
- エンドポイントは何が必要か。
- リクエストとレスポンス形式はどうするか。
- エラー形式はどうするか。
- ページング、検索、ソートは必要か。
- レート制限は必要か。
- 外部公開の範囲はどこまでか。

## FrontEnd の質問セット

- どの画面が必要か。
- 画面遷移はどうするか。
- 状態管理は必要か。
- コンポーネント分割はどうしたいか。
- ローディング、空状態、エラー状態は必要か。
- モバイル対応は必要か。
- デザインシステムはあるか。
- ブラウザ対応の範囲はどこまでか。

## Front の質問セット

- どの画面が必要か。
- 画面ごとの入力と表示は何か。
- 認証と認可はどうするか。
- 一覧、詳細、編集、削除のどれが必要か。
- ファイルアップロードは必要か。
- CSV や印刷などの補助機能は必要か。
- 画面状態はどう分けるか。

## 使い分け

- 共通質問で土台を作る。
- 該当しない種類は聞かない。
- 画面系は `Front` と `FrontEnd` を混同しない。
- バッチ処理は UI 質問を含めない。
- API は画面仕様ではなく契約仕様に寄せる。
