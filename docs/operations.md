# 運用手順

## リリース前

1. 本番DBをバックアップし、復元手順も検証する。
2. `php artisan migrate --force` を実行する。
3. `php artisan test` と `npm run build` が成功することを確認する。
4. 管理者で年間登録の申請→入金確認→承認、退会→再入会、CSV出力を確認する。

## 定期運用

- スケジューラを毎分実行する（cron例: `* * * * * cd /path/to/app && php artisan schedule:run`）。毎日9時に成績未入力、9時15分に年間登録期限通知をキューへ投入する。
- ワーカーを常駐させる（`php artisan queue:work --tries=3`）。`QUEUE_CONNECTION=database` の場合は jobs テーブルを利用する。
- `MAIL_MAILER=smtp`、SMTPホスト・ポート・認証情報・送信元を本番 `.env` に設定し、承認通知と期限通知をテスト送信する。期限通知は有効アカウントだけに30日前・7日前・期限切れ後に各年度・種別ごと一度だけ送信され、個別の送信失敗は他のジョブを止めずログへ記録する。
- 年間登録レポートは管理画面の「年度別レポート」から条件を指定して確認し、CSVまたは印刷用画面で出力する。申請7日超過・入金確認3日超過はダッシュボードのリンクから優先的に処理する。
- 日次バックアップを保管し、少なくとも月1回は復元確認を行う。
- 管理操作は `audit_logs` で変更対象と項目を確認する。個人情報の値そのものはログに保存しない。

## 退会・再入会

- 退会は会員を削除せず `inactive` にする。ログインと大会申込は停止する。
- 再入会時は管理者が会員編集で状態を `active` に戻す。既存の成績・申請・年間登録履歴を引き継ぐ。
